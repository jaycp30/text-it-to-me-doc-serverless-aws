   deps (`@aws-sdk/*` ^3.700.0, `luxon` ^3.5.0 where used — luxon is NOT in the
   Lambda runtime so it must be a dependency).

   medication helper with guardrails (only-current-prescription, no dose changes,
   no diagnosis, emergency redirect). Added `ChatFunction` + `POST /chat` route to
   `template.yaml`.
3. **template.yaml fixes** (found via `sam validate --lint`):
   - **Circular dependency (hard blocker)**: removed `NOTIFIER_FUNCTION_ARN` and
     `SCHEDULER_ROLE_ARN` from `Globals` (they referenced `NotifyUserFunction`,
     which is itself a function → self-reference). Re-added them only on
     `ProcessPrescriptionFunction` and `DailySummaryFunction`.
   - Added `LambdaInvokePolicy: { FunctionName: !Ref NotifyUserFunction }` to
     `DailySummaryFunction` (it invokes NotifyUser but lacked permission).
   - Bumped runtime `nodejs20.x` → `nodejs24.x` (20.x is EOL; creation disabled
     from 2026-06-01).
4. **Frontend**: chat fetch in `App.jsx` now sends
   `{ message, history, prescription: rx || MOCK_RX }` so the deployed chat Lambda
   has prescription context.
5. **DEPLOY.md**: authored the full runbook + added STATUS banner marking local
   work complete.

## Next Steps (user does these in fresh session, from DEPLOY.md)
1. **Step 3 — Bedrock**: Console → Bedrock → Model access → enable Anthropic Claude
   in ap-northeast-1. Then run:
   `aws bedrock list-inference-profiles --region ap-northeast-1 --query "inferenceProfileSummaries[?contains(inferenceProfileId,'anthropic')].inferenceProfileId" --output table`
   Pick an **`apac.anthropic.claude-…`** ID (Tokyo uses `apac.` prefix, NOT `us.`).
2. **Step 4 — Notifications (both)**:
   - SES: `aws ses verify-email-identity --email-address <sender> --region ap-northeast-1`
     and verify any test recipients (sandbox only sends to verified addresses).
   - SNS SMS: Console → SNS → Text messaging → add+verify a sandbox destination
     number; set a monthly spend limit. +63 (PH) is carrier-dependent; test own
     number first; E.164 format.
3. **Step 5 — Deploy backend**:
   `sam build && sam deploy --guided --region ap-northeast-1 --stack-name text-it-to-me-doc --capabilities CAPABILITY_IAM CAPABILITY_NAMED_IAM --parameter-overrides "BedrockModelId=<apac id from step 3>" "SesFromEmail=<verified sender>"`
   Copy the **`ApiUrl`** output. Smoke test with the curl `POST /chat` example in
   DEPLOY.md (verifies Bedrock + API GW + chat Lambda).
4. **Step 6 — Frontend / Amplify**: `git init`, create `.gitignore`
   (node_modules/, dist/, .DS_Store, .aws-sam/, .env), commit, push to GitHub.
   Amplify console → host web app → connect repo/branch → set **appRoot `frontend`**
   (use the `amplify.yml` in DEPLOY.md; Vite output dir is **`dist`** not `build`).
   Set env var **`VITE_API_BASE_URL`** = the ApiUrl. Do NOT set
   `VITE_ANTHROPIC_KEY` in prod. After getting the Amplify URL, tighten CORS in
   `template.yaml` (S3 bucket + RxApi `AllowOrigins`) and redeploy.
